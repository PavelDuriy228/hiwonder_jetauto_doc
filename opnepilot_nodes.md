 ---
  Что взять из openpilot для JetAuto

  Что можно скопировать напрямую

  common/pid.py — PID с двумя важными фишками:
  - Коэффициенты Kp/Ki/Kd задаются как таблица по скорости: [[v1, v2], [kp1, kp2]] — при разных скоростях робота разные
  коэффициенты
  - Anti-windup: интегратор перестаёт расти, если управление уже насыщено (уткнулось в предел). Без этого машина
  "заносит" после поворота

  common/simple_kalman.py — 1D Kalman Filter:
  - Применяется для фильтрации показаний лидара и ультразвука. Убирает скачки измерений

  common/filter_simple.py — FirstOrderFilter:
  - LP-фильтр: x_new = (1-alpha)*x + alpha*x_input. Сглаживает команды скорости, чтобы не было рывков

  ---
  Архитектурные идеи

  Трёхуровневое управление из controlsd.py:
  100Hz: LongControl + LatControl → /cmd_vel
   20Hz: Vision/Lidar → curvature, obstacles
   30Hz: Camera → lane detection
  У openpilot два независимых контроллера — продольный (скорость) и поперечный (поворот). Это важно: они не мешают друг
  другу и настраиваются отдельно.

  State machine из longcontrol.py:
  off → starting → pid → stopping
  Вместо того чтобы просто подавать скорость, робот сначала "стартует" (даёт начальный импульс), потом держит скорость
  PID'ом, потом плавно тормозит. Именно это даёт плавное движение без рывков.

  Ограничения по рывку из drive_helpers.py:
  max_curvature_rate = MAX_LATERAL_JERK / v²
  new_curvature = clip(new_curvature,
      prev - max_curvature_rate * dt,
      prev + max_curvature_rate * dt)
  Кривизна поворота не может меняться мгновенно — ограничена физикой. Это предотвращает резкие развороты, которые роняют
   робота на повороте.

  ---
  Что адаптировать под робота

  latcontrol_pid.py → управление поворотом:

  В оригинале управляет углом руля автомобиля. Для JetAuto нужно заменить "угол руля" на "угловую скорость" (angular.z в
   /cmd_vel). Логика та же: считаем ошибку от желаемой траектории, подаём PID, ограничиваем рывок.

  radard.py + simple_kalman.py → трекинг препятствий с лидара:

  В оригинале — для радара автомобиля. Для JetAuto: каждый кластер точек лидара — это "трек". Kalman фильтр
  предсказывает куда движется объект. Если робот едет на объект — торможение. Это намного лучше чем просто "если
  расстояние < 30 см — стоп".

  desire_helper.py → state machine объезда:
  off → preparing → executing_left/right → finishing
  Когда лидар видит препятствие, робот не просто тормозит, а выбирает: объехать слева или справа (смотрит, где больше
  места), плавно выполняет манёвр, возвращается на курс.

  locationd/pose_kf.py → EKF для позиционирования:

  18-мерный вектор состояния (x, y, θ, v, ω + смещения IMU). Объединяет IMU + одометрию колёс + данные лидара. Даёт
  точную оценку положения робота даже при скользком поле. На JetAuto упростить до 6 состояний (x, y, θ, vx, vy, ω).

  Этап 1 — Базовый контроллер (то, что уже есть + улучшения):
  - Скопировать pid.py и filter_simple.py без изменений
  - Переписать cone_follow_node.py используя LongControl state machine

  Этап 2 — Удержание полосы:
  - OpenCV детекция линий (Canny + HoughLines) вместо нейросети
  - LatControlPID с ограничением кривизны из drive_helpers.py

  Этап 3 — Объезд препятствий:
  - Трекинг кластеров лидара через KF1D из simple_kalman.py
  - Адаптированный desire_helper.py для выбора манёвра

  Этап 4 — Сенсорный fusion:
  - Упрощённый EKF (6 состояний): IMU + энкодеры колёс + лидар

### Что важно знать по каждой фазе
- Фаза 1 (PID + recorder) — самая важная. dataset_recorder.py должен запускаться с первого дня, даже пока ты просто тестируешь движение. Каждая секунда ручного управления — это обучающий пример. Формат: {timestamp, frame_path, speed_left, speed_right, ultrasonic_cm}.

- Фаза 2 (данные) — узкое место всего проекта. Нейросети нужно разнообразие: повороты в обе стороны, разное освещение, разная скорость. Минимум — 2 часа чистых данных. Аугментация (горизонтальный flip + зеркалирование команд) удвоит датасет бесплатно.
- Фаза 3 (ML) — обучать на ПК или Google Colab, не на роботе. Архитектура простая: MobileNetV2 (предобученный, лёгкий) → срезать голову → добавить regression head на 2 выхода (скорость L и R). Время обучения — часы, не дни.
- Фаза 4 (деплой) — ключевое решение здесь: hybrid_pilot.py. Не выбрасывать PID, а оставить его как страховку. Если нейросеть неуверена (большая дисперсия выходов при нескольких прогонах с dropout) — передать управление PID. Именно так сделан openpilot в ранних версиях.
- Фаза 5 (итерации) — session_reviewer.py это твой главный инструмент. Смотришь видео, отмечаешь моменты где робот ошибся, эти моменты идут в дообучение с повышенным весом. Через несколько циклов модель перестаёт делать эти ошибки.
